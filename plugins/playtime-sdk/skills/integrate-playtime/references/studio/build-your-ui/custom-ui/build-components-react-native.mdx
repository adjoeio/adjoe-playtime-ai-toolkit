## New Offers

**Models and fields:** `PlaytimeCampaign.appName`, `iconImage`, `eventConfig`, and
`eventConfig.totalCoinsPossible`.

```tsx
function NewOfferCard({ campaign }: { campaign: PlaytimeCampaign }) {
  return (
    <View>
      {campaign.iconImage ? <Image source={{ uri: campaign.iconImage }} /> : null}
      <Text>{campaign.appName}</Text>
      {campaign.eventConfig?.totalCoinsPossible != null ? (
        <Text>Earn up to {campaign.eventConfig.totalCoinsPossible} coins</Text>
      ) : null}
    </View>
  );
}
```

Preserve SDK order and report a `DEFAULT` impression when the full card is visible.

## Installed Offers

**Models and fields:** `PlaytimeCampaign.status`, `isCompleted`, `totalCoinsCollected`, and
`totalCoinsPossible`.

```tsx
function InstalledOfferCard({ campaign }: { campaign: PlaytimeCampaign }) {
  const collected = campaign.eventConfig?.totalCoinsCollected ?? 0;
  const possible = campaign.eventConfig?.totalCoinsPossible;

  return (
    <View>
      <Text>{campaign.appName}</Text>
      <Text>{collected} coins collected</Text>
      {possible ? (
        <Text>{Math.round((collected / possible) * 100)}% complete</Text>
      ) : null}
      {campaign.isCompleted ? <Text>All rewards completed</Text> : null}
      {campaign.status === PlaytimeCampaignStatus.INSTALLED ? (
        <Text>Ready to play</Text>
      ) : null}
    </View>
  );
}
```

Use enum constants, not lowercase status strings. Add interactions using the methods described in
[Use the SDK](./use-sdk-react-native.mdx).

## Promotions

**Models and fields:** `PlaytimeCampaign.promotion`, `promotion.boostFactor`, `targetingType`,
`totalCoinsPossible`, and `totalOriginalCoinsPossible`.

```tsx
function PromotionTotal({ campaign }: { campaign: PlaytimeCampaign }) {
  const current = campaign.eventConfig?.totalCoinsPossible;
  const original = campaign.eventConfig?.totalOriginalCoinsPossible;
  if (!campaign.promotion || current == null) return null;
  const label =
    {
      AdvertiserLevel: 'Advertiser promotion',
      UserLevel: 'Special promotion',
      AllUsers: 'Promotion',
    }[campaign.promotion.targetingType ?? ''] ??
    campaign.promotion.name ??
    'Reward boost';

  return (
    <View>
      <Text>{label}</Text>
      {original != null && original < current ? (
        <Text>
          {original} → {current} coins
        </Text>
      ) : (
        <Text>{current} coins</Text>
      )}
    </View>
  );
}
```

Check `targetingType` in the SDK response to identify the applied promotion and drive the UI. Use a
generic fallback for unknown values. Current amounts already include promotions; never multiply
them by `boostFactor` again. See [User Level Promos](../../../resources/user-level-promos.md) for
`promotionTag` setup and [Advertiser-Level Promotions](../offer-api.mdx#advertiser-level-promotions-alp)
for additional ALP guidance.

## Time-Based Rewards (Android Only)

**Models and fields:** `eventConfig.timeBasedActions[]`, `secondsToNextLevel`, `playDuration`,
`level`, `amount`, and `rewardedAt`.

```tsx

function TimeBasedRewards({ campaign }: { campaign: PlaytimeCampaign }) {
  if (Platform.OS !== 'android') return null;
  const actions = campaign.eventConfig?.timeBasedActions ?? [];

  return (
    <View>
      {actions.map((action, index) => (
        <Text key={index}>
          {action.name ?? `Level ${action.level ?? ''}`}: {action.playDuration ?? 0}s ·{' '}
          {action.amount} coins
        </Text>
      ))}
    </View>
  );
}
```

Both durations use seconds. Guard this UI by platform; iOS does not support time-based rewards.

## Repeatable Rewards

**Models and fields:** `PlaytimeRewardAction.rewardsCount`, `completedRewards`, and `amount`.

```tsx
function RepeatableProgress({ action }: { action: PlaytimeRewardAction }) {
  const target = action.rewardsCount;
  if (target == null || target <= 1) return null;
  const completed = Math.min(Math.max(action.completedRewards ?? 0, 0), target);

  return (
    <Text>
      {completed} of {target} completed · {action.amount} coins each
    </Text>
  );
}
```

Repeatability belongs to sequential or bonus actions.

## Cashback

**Models and fields:** `eventConfig.cashbackReward`, `exchangeRate`,
`maxLimitPerCampaignCoins`, `pendingRewards`, `completedRewards`, reward `events`, `coins`,
`receivedAt`, and `processAt`.

```tsx
function CashbackSection({ campaign }: { campaign: PlaytimeCampaign }) {
  const cashback = campaign.eventConfig?.cashbackReward;
  if (!cashback) return null;

  return (
    <View>
      <Text>Cashback</Text>
      {cashback.cashbackDescription ? <Text>{cashback.cashbackDescription}</Text> : null}
      {cashback.exchangeRate != null ? (
        <Text>{cashback.exchangeRate} coins per USD</Text>
      ) : null}
      <Text>Processing: {cashback.pendingRewards?.totalCoins ?? 0} coins</Text>
      {cashback.pendingRewards?.events.map((event, index) => (
        <View key={`${event.receivedAt ?? 'pending'}-${index}`}>
          <Text>{event.coins ?? 0} coins — processing</Text>
          {event.processAt ? <Text>Expected processing: {event.processAt}</Text> : null}
        </View>
      ))}
      <Text>Completed: {cashback.completedRewards?.totalCoins ?? 0} coins</Text>
    </View>
  );
}
```

Cashback attribution can be delayed. Show `pendingRewards` as processing and keep it separate from
`completedRewards`; never present pending coins as collected. `receivedAt` indicates when an event
was received and `processAt` indicates its processing time. Refresh installed campaigns so the UI
can move rewards from processing to completed. Hide the section only when the model is absent.
Promotions do not apply to cashback.

## Time-Boosted Rewards

**Models and fields:** `PlaytimeRewardAction.timedCoins`, `originalCoins`,
`timedCoinsDuration`, and `boosterExpiresAt`.

```tsx
function TimeBoost({ action }: { action: PlaytimeRewardAction }) {
  if (action.timedCoins == null || action.timedCoins <= 0) return null;

  return (
    <View>
      <Text>Limited-time boost: {action.timedCoins} coins</Text>
      {action.timedCoinsDuration != null ? (
        <Text>Complete within {action.timedCoinsDuration} minutes</Text>
      ) : null}
      {action.boosterExpiresAt ? (
        <Text>Boost expires: {action.boosterExpiresAt}</Text>
      ) : null}
    </View>
  );
}
```

Prefer `boosterExpiresAt` after installation. Promotions do not apply to timed values.

## Pending Installs

**Models and fields:** `PlaytimeCampaign.status` and `PlaytimeCampaignStatus`.

```tsx
function InstallationStatus({ campaign }: { campaign: PlaytimeCampaign }) {
  switch (campaign.status) {
    case PlaytimeCampaignStatus.PENDING:
      return <Text>Verifying installation…</Text>;
    case PlaytimeCampaignStatus.INSTALLED:
      return <Text>Installed — keep playing</Text>;
    case PlaytimeCampaignStatus.FAILED:
      return <Text>Not eligible for rewards</Text>;
    default:
      return <Text>Available to install</Text>;
  }
}
```

Pending campaigns come from `getInstalledCampaigns`. Refresh on app foreground or user action;
do not poll continuously.
