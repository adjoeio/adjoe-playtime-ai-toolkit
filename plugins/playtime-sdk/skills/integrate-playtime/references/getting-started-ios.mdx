This guide walks you through adding the Playtime SDK to your iOS project.

:::info[Shared Setup]
This setup is required for both [Catalog Integration](./standard-integration/overview.md)
and [Studio Integration](./studio/overview.md). Complete it once, then continue with
your chosen integration.
:::

## Add the Dependency

<Tabs groupId="ios-pm">
<TabItem value="spm" label="Swift Package Manager">

1. In Xcode: File → Add Package Dependencies
2. Enter the repository URL: `https://github.com/adjoeio/adjoe-monetize-spm`
3. Select version 5.0.0-beta.4

</TabItem>
<TabItem value="cocoapods" label="CocoaPods">

1. Add the adjoe spec repo source and the SDK to your `Podfile`:

```ruby
source 'https://github.com/adjoeio/PlaytimeSpecExternal.git'

platform :ios, '14.0'

target 'MyApp' do
  use_frameworks!
  pod 'PlaytimeSDK', '5.0.0-beta.4'
end
```

2. Install the dependency:

```bash
pod install --repo-update
```

3. Open the `.xcworkspace` file generated by CocoaPods.

</TabItem>

## Configure App Attest

The Playtime SDK uses [Apple's DeviceCheck APIs](https://developer.apple.com/documentation/devicecheck) to verify that the app is running on a real device without malicious alterations. **You must complete the following steps**, even if the app builds normally.

:::note
App Attest is not available in the iOS Simulator. Test the integration on a physical device.
:::

**Part 1: Enable App Attest**

1. Go to [Apple Developer Certificates, IDs & Profiles](https://developer.apple.com/account/resources/identifiers/list)
2. Select your app ID
3. Ensure **App Attest** is enabled under **Capabilities**

![Enable App Attest](</img/rewarded-solutions/playtime-sdk-integration/ios/image%20(1).avif>)

**Part 2: Add Capabilities in Xcode**

1. Select the project in the **Project Navigator**
2. Select your **target**
3. Go to **Signing & Capabilities**
4. Add the **App Attest** capability

![Add App Attest capability](</img/rewarded-solutions/playtime-sdk-integration/ios/image%20(2).avif>)

**Part 3: Generate Credentials**

1. **Private Key:** Generate a private key for the AppAttest service and download the `.p8` file. [Instructions](https://developer.apple.com/help/account/manage-keys/create-a-private-key). Only the DeviceCheck/AppAttest service should be enabled.

![Generate private key](</img/rewarded-solutions/playtime-sdk-integration/ios/image%20(3).avif>)

2. **Key ID:** Note the [key identifier](https://developer.apple.com/help/account/keys/get-a-key-identifier/) associated with the service.
3. **Team ID:** Note the 10-character Apple Team ID, for example `M4CAP9HPPJ`.
4. **Bundle ID:** Confirm that the app's Bundle ID, for example `com.my.app`, matches
   the application configured in the Monetize Dashboard.

:::danger
The per-device data used by [DeviceCheck](https://developer.apple.com/documentation/devicecheck) is global. Only adjoe should be permitted to set or update the two bits for a device. You can still use DeviceCheck with Firebase as this does not interfere with our checks.
:::

**Part 4: Upload Credentials**

Add the credentials under _Edit Application_ in the [Monetize Dashboard](https://monetize.adjoe.io/).

Provide each value in its corresponding field:

| Dashboard field | Value                                                     |
| --------------- | --------------------------------------------------------- |
| Team ID         | Your 10-character Apple Team ID, for example `M4CAP9HPPJ` |
| Key identifier  | The Key ID shown for the DeviceCheck/App Attest key       |
| Private key     | The downloaded `.p8` private key requested by the form    |
| Bundle ID       | The exact Bundle ID registered for this application       |

![Upload App Attest credentials in the Monetize Dashboard](/img/playtime-studio/integration/ios/upload-credentials.png)

Apple lets you download a `.p8` private key only once. Store it securely and never add
it to your app bundle or source repository.

## Configure Production Environment

After adding the App Attest capability, configure your entitlements file to use the **production** environment.

**Set to production environment:**

1. Open the `.entitlements` file (created automatically by Xcode when you added App Attest)
2. Find the key: `com.apple.developer.devicecheck.appattest-environment`
3. **Set the value to `production`** (NOT `development`)

Your entitlements file should look like this:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>com.apple.developer.associated-domains</key>
    <array>
        <string>webcredentials:prod.adjoe.zone</string>
    </array>
    <key>com.apple.developer.devicecheck.appattest-environment</key>
    <string>production</string>
</dict>
</plist>
```

**Verify build configurations:**

1. In Xcode, go to your Target → Build Settings
2. Search for "Code Signing Entitlements"
3. Ensure **both Debug and Release** configurations point to the same entitlements file with `production` set

:::warning[Why production is required]
Unlike typical Apple services, the adjoe backend does **not** support development App Attest attestations. Both your development/testing builds and production builds must use the `production` environment. Using `development` will cause authentication failures.
:::

:::caution[Troubleshooting]
If you see errors related to "AAGUID not found" in your logs, it means your entitlements are still set to `development`. Double-check steps above, clean your build folder (Product → Clean Build Folder), and rebuild.
:::

## App Tracking

While the IDFA parameter is not required, we strongly recommend including it. It helps attribute installs and ensures that users are rewarded correctly.

Request App Tracking Transparency authorization before showing games to users. If the
user authorizes tracking, the Playtime SDK reads the IDFA directly through Apple's API.
You do not need to pass the IDFA to the SDK or reinitialize the SDK after the user
responds.

```swift
import AppTrackingTransparency

ATTrackingManager.requestTrackingAuthorization { status in
    // Continue your app flow.
}
```

:::note
Request authorization while your app is active, for example from a button tap or after the
first screen appears. If you request it during launch, before the app is active, iOS returns
`.notDetermined` without showing the prompt.
:::
